# URRF Universal Art Asset Forge v0.1

## Status

`CANDIDATE_ONLY` / `AAA_NOT_PROVEN`

The forge now has a runnable Genome → Provider Resolution → Provider Job → Candidate → Production Court → local GLB/LOD inspection → unified independent evidence-bundle verification → AAA Acceptance → Evidence Ledger path. A candidate-only batch → assembly → VSR projection path now binds materialized GLB/PBR bytes, selected LODs, integer placements, cells, and cross-asset roots, then imports, CPU-rasterizes, and browser-GPU-renders an aggregate VSR scene. The browser fixture now also records a rooted 12-frame local budget sample with warmup/steady-state timings and VSR logical residency. A separate holdout evaluator now reruns new-seed character/prop candidates against a rooted baseline batch, checks profile coverage, structural inspection, root isolation, and fails closed on root reuse. The profile coverage evaluator now exercises all nine declared asset families and records whether each route is a built-in reference, an unbound external contract, an executed Provider, or an unresolved capability. The Provider preflight evaluator now binds every profile route to the registered manifest root, adapter health, runner/command binding, license audit and release blocker state, while keeping preflight non-executing and candidate-only. The Provider execution receipt now binds the exact request, Job/Result/Failure roots, materialized file roots, acceptance/ledger roots, and an explicit `NOT_RUN` replay boundary for reference, injected, contract-only and unresolved paths. A separate replay evaluator now reruns a bound request in an isolated output directory, compares request/provider/mode and output roots, distinguishes bounded deterministic root equality from nondeterminism, and keeps missing external runtimes `NOT_RUN`. Every generation now also emits a non-executing multi-stage Provider Pipeline Plan that binds base generation, rigging/animation and optional geometry-refinement stages to capability aliases, declared outputs, runtime binding and explicit blockers. A candidate Pipeline Executor now runs only injected or explicitly configured runtime stages, chains each stage to the preceding result root, materializes isolated outputs, and emits a rooted stage execution receipt; a Pipeline Artifact assembler now packages those stage outputs into one role-indexed reusable candidate artifact with a bound primary output; contract-only, built-in-reference and unresolved routes remain explicit non-execution boundaries. The committed reports are deliberately `BLOCKED`: the deterministic RAGF reference provider produced structurally valid candidate files with bound PBR textures and a decreasing three-level LOD sequence, but it did not supply all evidence required for an AAA production claim.

The RNCS core now also exposes a rooted `FactWorldTreeRef` candidate contract and publishes the missing v0.3 P0 Schema surface for Reality Horizon, Interest Graph, Consistency Profile, Authority Lease, Replication Envelope, Transport Profile, Power Profile, and Resource Budget. A deterministic child-process Provider fixture now exercises the configured external-process adapter path through stdin/stdout JSON and preserves the same candidate-only authority boundary. URRF also now binds independently rooted asset-family Genomes into a deterministic cross-family component DAG, lowers its attachment/dependency nodes into explicit `NOT_EXECUTED` Provider/VSR inputs, reuses the existing Provider Pipeline Executor to execute each component in dependency order with sealed result-root context chaining, and packages the completed component artifacts into a stage-path-correct resource catalog with local byte verification. These additions prove contract closure and process binding locally; they do not prove external model weights, high-resolution generation, target hardware, or AAA quality.

The component resource catalog now also lowers into a representation-aware candidate directory. It preserves the exact URRF kind and Provider binding, emits RNCS representation references for completed stages, classifies each physical resource into a VSR kind from its role/format, exposes a byte-rooted VSR catalog, and supplies RSR bounds/LOD/residency observation inputs without reconstruction or canonical proposals. A bounded import-execution seam now requires an explicit per-kind handler plus independent receipt verification, rehashes loaded bytes, and keeps unbound handlers `NOT_RUN`. An explicit file-level `source_asset_id` now survives Provider normalization, pipeline materialization, Pipeline Artifact packaging, component assembly, and the VSR catalog; VSR non-mesh pages resolve only through that declared logical-to-physical binding and reject missing or ambiguous matches. A cross-package integration consumed all 20 materialized resources through the existing VSR streamer, exercised the actual RSR observation-candidate API, and executed one valid mesh through the existing VSR GLB importer; direct import for unbound kinds remains `NOT_EXECUTED`, and this is still local candidate evidence rather than AAA delivery.

The VSR consumer now also provides a rooted `composeSpatialSceneFragments` operation. Independently imported component scenes are remapped into isolated namespaces, placed below synthetic transform anchors, and revalidated as one candidate scene. The integration executes two component GLBs, decodes four embedded PNG PBR maps plus four external PNG PBR channels each, validates the matching eight-bone rig and four animation clips against each GLB skin/channel set, verifies five material-texture bindings per component, composes both scenes at their URRF transforms, compiles two visible VSR draws, and verifies the composition receipt; no canonical merge or target-device proof is implied.

The import report now also requires explicit resource coverage: every loaded VSR catalog asset must be declared as consumed or intentionally deferred, with duplicate, unknown, overlapping, and incomplete declarations failing closed. The VSR consumer now exposes a reusable glTF/PBR component handler that selects one or more mesh GLBs, binds complete independently materialized four-channel PBR packs per declared mesh/material index, requires an injected image decoder for external channels, optionally validates matching skeleton-rig and animation-clips manifests against the imported skin/channels, and returns the imported scene together with resource coverage. Multiple GLBs are imported independently and composed under isolated VSR namespaces; ambiguous external PBR ownership fails closed. The downstream seam now also exposes a sealed candidate-only per-kind importer registry: its portable manifest has a registry root, while execution requires the matching process-local resolver and binds that root into the import report. It also exposes a standalone rig/animation handler that converts the independent RAGF JSON contracts into a bone-only VSR scene, validates hierarchy/time/channel references, and makes missing rig binding explicit; with `fuseGeometry:true`, the same handler binds a unique same-stage GLB, validates skin joint names and parent hierarchy, and imports an actual fused geometry/rig/animation VSR scene; with `fuseExternalPbr:true`, it reuses the glTF/PBR handler to consume and decode a complete same-stage four-channel external material pack and bind those channels into the fused scene. A particle-preset handler now validates a real RAGF `rsr.particle-preset.v0.4` JSON resource and normalizes its emitter semantics into a rooted VSR candidate while explicitly deferring unrelated mesh/PBR/rig/animation resources; the separate `lowerVsrParticleEmitterToSpatialScene()` path deterministically lowers that candidate into a bounded cross-billboard scene consumed by the existing CPU/WebGPU spatial renderer, with local draw/pixel roots and tamper verification. GPU-native simulation, sprite/flipbook resources, volume rendering, target-device execution and AAA quality remain open. The current component integration therefore consumes actual PNG PBR channels and matching rig/animation resources, fuses one real directory animation component with its geometry and four external PBR channels, and records particle emitter coverage; body remains `PARTIAL` and blade reaches `COMPLETE` under the directory's actual resource sets. Separate unit paths cover two meshes/two per-material packs in one GLB, two independent GLBs, fused geometry/rig/animation with and without external PBR, and one particle emitter candidate plus spatial scene lowering.

The VSR consumer now also has a generic non-mesh descriptor/page candidate compiler for `sdf`, `voxel`, `point-cloud`, `gaussian-splat`, `neural-field`, `curve`, and `material`, plus a factory that creates all seven explicit per-kind handler/verify bindings for URRF registration. It verifies one manifest plus ordered opaque payload pages, identity, bounds, declared format, byte length, content/resource/candidate roots, alias normalization, complete consumed/deferred coverage, and explicit logical-page to physical-resource bindings; the Draft 2020-12 manifest fixes `candidate_only=true` and `authoritative=false`. Its generic result is intentionally `renderStatus=NOT_IMPLEMENTED`; the fixed-record point-cloud profile has a separate bounded scene lowerer, the fixed-record curve profile has a bounded CPU/WebGPU-compatible ribbon lowerer, the fixed-grid RGBA8 voxel profile has a bounded cube-node lowerer, the fixed-grid f32 SDF profile has a bounded CPU marching-tetrahedra surface lowerer with gradient normals, the fixed-record Gaussian profile has a bounded decoder plus transparent pose/scale-aware cross-billboard approximation, and the fixed-profile neural-field handler evaluates a bounded 3→16→4 tanh MLP on CPU before reusing the surface lowerer. Representation-specific arbitrary NeRF decoding/training, native anisotropic Gaussian rendering, target hardware, and AAA acceptance remain open.

The new `@taowind/urrf-vsr-art-asset-bridge` integration package now binds the VSR glTF/PBR, standalone rig/animation, particle, and seven non-mesh handlers into one explicit URRF/LWR sealed registry covering all eleven current representation kinds. LWR remains responsible for component selection, byte rehashing, coverage, and execution reports; VSR remains responsible for interpretation and receipt verification. The default bridge is descriptor-only, while explicit spatial mode connects particle, SDF, voxel, point-cloud, Gaussian, neural-field, and curve candidates to their bounded spatial lowerers; material remains descriptor-only. The bridge callback is released only after VSR verification, and the registry remains candidate-only; GPU-native paths, target hardware and AAA acceptance remain separate gates.

The particle boundary has moved one step further: `lowerVsrParticleEmitterToSpatialScene()` consumes the verified VSR emitter candidate and deterministically creates a bounded cross-billboard scene with particle, scene and pixel/frame roots. Existing VSR CPU/WebGPU spatial paths can consume this candidate scene, and the focused regression covers repeated-root equality, transparent draw generation and tampered-result rejection. This is still a bounded presentation lowerer; GPU-native simulation, sprite/flipbook resources, volume rendering, target-device execution and AAA visual acceptance are not proven.

## RCL Gap

RCL currently does not own a proven universal art-asset primitive that directly expresses and executes all of the following as one canonical semantic:

- asset-family profiles spanning characters, creatures, props, vehicles, structures, environments, vegetation, resources and VFX;
- topology, UV, normal, PBR surface, rig, animation, LOD, collision and target-platform contracts;
- Provider selection, external execution, source/model/weight/license provenance and safe result materialization;
- independently verified provenance/license, art-direction, human-review, and quality proofs as non-substitutable acceptance evidence.
- multi-asset isolation, per-asset acceptance accounting, unified evidence coverage, and cross-asset artifact-root indexing without granting a batch authority to deduplicate or write RNCS truth.
- binding materialized Forge files to a reusable multi-asset assembly and lowering selected LOD/placement/cell references into a VSR import seam without granting VSR or the Provider canonical RNCS write authority.
- materializing a dependency-complete VSR catalog from separate mesh and PBR files, preserving byte roots across the streamer, and adapting external PBR channels into a glTF material without mutating the source GLB.
- a canonical performance-evidence primitive that separates warmup from sustained frames, binds timing/resource budgets to the same scene/frame roots, and keeps local-host measurements distinct from target-device/physical-telemetry claims.
- a canonical holdout-regression primitive that binds a new-seed batch to an explicit baseline, checks profile coverage and structural file gates, rejects genome/candidate/Forge root reuse, and keeps structural generalization separate from AAA acceptance.
- a canonical all-profile coverage primitive that binds each declared profile to its resolution/execution facts, distinguishes contract-only from executed/unresolved routes, rejects silent fallback, and preserves the candidate-only authority boundary.
- a canonical asset-kind/profile registry primitive that rejects unregistered asset kinds instead of silently routing them into the `prop` family.
- a canonical Provider preflight primitive that binds each profile route to manifest identity, adapter health, injected/external runtime binding, license-audit blockers and explicit non-execution/readiness boundaries.
- a canonical Provider execution/replay primitive that binds one request to Job/Result/Failure, candidate/court, materialization, file inspection, acceptance and ledger roots, reruns the request in an isolated directory, compares output roots, and records missing external runtime as `NOT_RUN` rather than claiming determinism.
- a canonical multi-stage Provider pipeline primitive that maps Profile requirements to ordered generation, rigging/animation and refinement stages, preserves capability/output aliases, distinguishes contract-only from runtime-bound stages, and records stage execution/chaining without granting authority.
- a canonical pipeline-artifact primitive that packages completed stage outputs, binds the primary stage and role-indexed materialized files, and preserves the candidate-only boundary for later assembly/VSR lowering.
- a canonical cross-family component-graph primitive that binds independently rooted asset Genomes, representation kinds, attachment transforms, dependency edges, and deterministic lowering order without merging bytes or granting Provider commit authority.
- a canonical multi-component execution primitive that reuses the Provider Pipeline lifecycle, passes sealed dependency result/output roots between components, isolates component artifacts, and aggregates execution without granting the composition commit authority.
- a canonical component-assembly/resource-catalog primitive that binds completed component Pipeline Artifacts, graph transforms, stage-relative paths, physical byte roots, and partial/blocking state without merging bytes or granting VSR/RSR/RNCS commit authority.
- a canonical representation-aware consumer directory that preserves every URRF representation kind, binds completed Provider stages to RNCS representation references, projects physical resources into a VSR stream catalog, and defers RSR observation execution without inventing reconstruction or canonical state.
- a canonical representation-import execution primitive that requires an explicit per-kind consumer handler, an independent receipt verifier, physical byte rehashing, and explicit `EXECUTED`/`BLOCKED`/`FAILED`/`NOT_RUN` status without mutating the representation directory or granting consumer commit authority.
- a downstream VSR scene-fragment composition primitive that remaps meshes, materials, textures, skins, animations, HLOD and streaming references into isolated namespaces, applies component transforms through synthetic anchors, and seals a candidate scene receipt without changing RNCS truth.
- a canonical resource-consumption coverage primitive that binds each executed handler to the complete VSR catalog asset set, distinguishes consumed resources from intentionally deferred resources, and rejects silent omissions or cross-component claims.
- a canonical representation-specific importer registry/IR that can select compatible mesh/material/texture/rig/animation resources, bind external channel semantics, aggregate independently owned mesh files, and prove complete decoded consumption across providers without conflating a downstream VSR handler with RCL ownership.
- a downstream non-mesh descriptor/page candidate-import primitive that roots opaque representation data and bounds; explicit Provider `source_asset_id` bindings connect logical manifest pages to physical catalog resources and fail closed on missing/ambiguous mappings; the fixed-record point-cloud profile has a bounded CPU/WebGPU-compatible billboard lowerer, the fixed-record curve profile has a bounded ribbon lowerer, the fixed-grid RGBA8 voxel profile has a bounded cube lowerer, the fixed-grid f32 SDF profile has a bounded marching-tetrahedra surface lowerer, the fixed-record Gaussian profile has a bounded decoder plus transparent cross-billboard approximation, and the fixed-profile neural-field profile has bounded CPU MLP evaluation plus surface lowering, all with local root/tamper evidence, while arbitrary NeRF/model training and native anisotropic Gaussian rendering remain open and RCL ownership plus their representation-specific runtime donors remain open.

The implementation therefore remains a downstream URRF/RNCS seam and records the missing capability instead of silently lowering it into another language or declaring RCL completion. Candidate absorption into RCL remains pending primitive/IR design, regression cases, K400 coverage and Integration Court decision.

## Donor Advantage and Reuse

`reality-asset-genesis-fabric` is the donor for Asset Intent/Genome, deterministic reference generation, Provider Adapter/Job/Result/Failure lifecycle, external Provider manifests, adapter health checks, license audit, Production Court and Evidence Ledger. The new URRF layer only adds the universal profile/representation/acceptance envelope, the rooted cross-family component graph and lowering order, component execution context/aggregate, component assembly/resource catalog, representation directory, representation-import execution report and its downstream candidate-only importer registry, independent evidence-bundle coordination, batch indexing, the explicit batch-to-assembly-to-VSR reference seam, Provider preflight evidence, execution/replay receipts, and the ordered Pipeline Plan/Executor/Artifact envelope on top of those existing contracts. RNCS `representation-ref`, VSR spatial streaming, the VSR glTF importer/receipt, and VSR scene-fragment composition/remapping are reused as downstream donors; VSR/RSR remain non-authoritative consumers and RNCS remains canonical world owner.
