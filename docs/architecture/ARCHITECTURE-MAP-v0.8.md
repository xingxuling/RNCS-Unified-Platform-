# Architecture Map — RNCS + Aetherworld Unified v0.8

## 当前目标
把 v0.7 已打通的“世界制造与权威闭环”升级为可真实行走、交互、联网和投影的 Playable Spatial World Runtime。

## 主 Skill
V1 软件架构：RSR/VSR 运行时、数据契约、测试与版本演化。

## 辅助 Skill 与调用顺序
1. V3 系统架构：保持 RFE → RSR → Network → VSR 单一权威链。
2. V6 需求架构：把“可玩”编译为可测试行为。
3. V8 美术架构：只约束资产、材质、纹理与投影接口，不扩张为内容生产任务。

## 已知硬约束
- RSR 状态是世界物理事实；VSR 只能投影，不得回写权威。
- Network 继续同步 RSR 权威状态，不建立第二套物理模型。
- 不重复实现 v0.7 已有的 OBB SAT、Capsule–Capsule、权威帧、预测重放、Hermite 插值和 Correction Plan。
- 保持旧格式可读取；新格式必须显式版本化。

## 各层交付物
- RSR v0.8：持久接触缓存、空间分区、台阶/吸附/移动平台角色控制、单向平台。
- VSR v0.7：glTF 2.0 导入、纹理资源、基础动画投影、真实参考渲染验证。
- 统一母工程 v0.8：可玩以太岛样例、双客户端权威与投影证据、完整回归与发布包。

## 跨层依赖
RSR 先冻结新状态字段与角色行为；Network验证兼容；VSR再消费权威状态和资产。

## 冲突裁决
物理真实性与权威一致性优先于视觉平滑；视觉质量不得改变 Authority Root。

## 暂不处理
不新增金融、企业、IoT、神经接口模块；不开发完整编辑器；不引入外部大型物理或渲染引擎。

## 最小验证闭环
双玩家在带台阶、移动平台、单向平台、门和纹理资产的以太岛中移动；两客户端权威状态一致；VSR生成独立 Presentation Root；回放结果确定性一致。
