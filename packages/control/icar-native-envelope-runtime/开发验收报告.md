# ICAR Native Envelope Runtime v0.5.0 开发验收报告

## 1. 验收结论

ICAR v0.5已形成可执行的RNCS原生闭环：

```text
自然语言意图
→ 开放能力注册与候选选择
→ Living Artifact候选修订
→ RNCS Transition Envelope
→ 权限与宿主能力授权
→ 显式Commit
→ RFE Generation
→ LAF Generation绑定
→ Commit后外部能力
→ 桌面与手机投影
```

本版本不再执行完成后才把结果适配为Envelope，而是从Plan阶段开始原生使用Envelope。

## 2. 核心边界

- ICAR负责意图、计划、候选差异和执行协调。
- LAF Revision负责对象内部修订。
- HNAC Snapshot负责宿主副本状态。
- ICAR Session负责过程记录。
- 只有RFE Generation表示权威现实已经改变。
- Preview阶段禁止不可逆外部副作用。

## 7. 未伪装完成的边界

1. 当前自然语言前端仍为确定性规则编译器，不是通用语言模型。
2. 开放能力注册表已经存在，但远程能力市场、网络发现和动态Provider加载尚未实现。
3. 通知能力为可验证模拟宿主能力，未接真实操作系统通知服务。
4. RFE使用本地文件后端，尚未接SQLite/PostgreSQL和联盟网络。
5. 权限解析支持Scope、Host与Risk，但完整Agent Authority Fabric尚未完成。
6. 当前投影为确定性桌面/手机HTML，不等于完整Observer-relative Projection生成器。

## 8. 下一步

下一优先级应为Capability Negotiation Protocol：把当前开放注册表扩展为正式能力声明、版本协商、输入输出契约、风险、成本、可逆性、证据与远程Provider协议。
