# 执行、权威与重基线协议 v0.2

## 沙箱执行

执行计划为每一步绑定：

- 能力ID；
- 预期前状态根；
- 预期后状态根；
- 操作内容；
- 逆操作。

Provider可以实现：

- `execute`：执行外部能力并返回证据；
- `rollback`：撤销外部副作用。

若后续步骤失败，RBF会逆序调用Provider回滚。只恢复内存状态而无法证明外部副作用恢复时，收据必须标记为`rollback_incomplete`。

## 权威批准

Merge Proposal默认要求权威决定。批准对象必须精确绑定Proposal Root；拒绝、过期、错配或被篡改的决定不能用于合并。

## 重基线

当主现实Generation变化后，旧候选不能直接继续合并。`rebaseWorkspace`会比较旧基础状态和新基础状态，并检查这些变化是否与候选操作路径重叠。

- 无重叠：可以干净重基线并重新仿真；
- 有重叠：输出可机器读取的漂移冲突；
- `reject`策略：直接拒绝有冲突的重基线。
