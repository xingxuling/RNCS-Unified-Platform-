# Reality Branch Fabric v0.2 架构

## 1. 核心对象

1. **Workspace**：绑定权威现实Generation、基础状态、情景、权重和权限策略。
2. **Candidate Branch**：描述假设、前置条件、操作、约束、不变量和预期影响。
3. **Branch Tree**：允许候选方案继续分叉，子分支继承父分支操作。
4. **Simulation**：在多个情景中计算候选状态、指标、违规和证据根。
5. **Comparison**：输出加权排序、Pareto前沿、冲突矩阵和推荐稳定度。
6. **Execution Plan**：把候选变化编译成逐步可执行计划与逆操作。
7. **Execution Receipt**：记录每一步Provider证据、状态根和回滚结果。
8. **Merge Proposal**：绑定基线、候选、仿真、执行与比较证据。
9. **Authority Decision**：明确谁批准、是否过期、适用哪个提案。
10. **Transition / RFE Commit Receipt**：把被批准的候选现实交给权威内核提交。

## 2. 为什么分支不是副本

传统分支往往只是复制文件。RBF分支描述的是：

- 从哪个权威Generation出发；
- 改变哪些现实状态；
- 为什么改变；
- 在哪些情景下成立；
- 违反哪些约束；
- 是否经过真实试运行；
- 谁批准；
- 最终是否由RFE提交。

## 3. 根绑定

每个阶段都通过SHA-256根绑定前一阶段：

```text
Workspace Root
→ Candidate Root
→ Scenario Root
→ Simulation Root
→ Comparison Root
→ Execution Plan Root
→ Execution Receipt Root
→ Merge Proposal Root
→ Authority Decision Root
→ Transition Root
→ RFE Commit Receipt Root
```

任何中途修改都会使后续验证失败。
