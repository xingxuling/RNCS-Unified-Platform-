# Reality Branch Fabric v0.2.0-alpha.1 开发验收报告

## 一、版本裁决

RBF v0.1解决的是“把多个候选方案表示出来并比较”；v0.2开始解决：

> **多个未来怎样在不污染主现实的前提下分叉、仿真、试运行、失败回滚、接受批准，并最终成为新的权威现实。**

因此本版的定位从“候选方案评分器”升级为：

> **候选现实执行器。**

## 二、已经闭合的主链

```text
RFE权威Generation
→ 候选现实树
→ 多情景模拟
→ 约束与不变量检查
→ Pareto与权重敏感性比较
→ 沙箱执行计划
→ 外部Provider执行与回滚
→ 执行收据
→ 合并提案
→ AAF式权威批准
→ RNCS Transition Envelope
→ RFE Commit Receipt
```

## 三、核心升级

### 1. 分支树

候选方案不再全部直接挂在主现实上。子分支可以继承父分支后继续改变，例如：

```text
快速方案
└─ 快速方案＋缓存保护
```

系统会按照父到子的顺序编译完整候选状态，并检测循环、缺失父分支和篡改根。

### 2. 多情景模拟

每个候选在基准、不利和有利情景中分别计算：

- 收益；
- 成本；
- 风险；
- 置信度；
- 持续时间；
- 硬约束和状态不变量。

聚合后输出预期指标、最坏指标和韧性分数。

### 3. 推荐稳定性

除了默认加权评分和Pareto前沿，本版还用平衡、安全、速度、成本四种偏好重新排序，输出推荐稳定度，避免把单一权重下的第一名伪装成绝对最优。

### 4. 沙箱执行与外部回滚

候选分支可编译成逐步执行计划。每一步绑定：

- 能力ID；
- 前后状态根；
- 操作；
- 逆操作；
- Provider执行证据。

若后续步骤失败，系统逆序调用Provider的`rollback`。如果外部副作用无法证明已撤销，收据会标记为`rollback_incomplete`，不能继续伪装成安全合并。

### 5. 权威边界

Merge Proposal默认要求权威批准。批准决定必须绑定正确Proposal Root，且不能是拒绝、过期或被篡改的决定。

### 6. 重基线

当主现实进入新Generation后，旧候选必须重新检查。系统会比较旧、新基础状态，并找出哪些主现实变化与候选写入重叠。

## 五、性能证据

环境：Node.js v22.16.0，Linux x64，三候选分支、三仿真情景，1000轮。

| 路径 | Median | P95 | Max |
|---|---:|---:|---:|
| 三分支仿真＋比较 | 2.633 ms | 4.082 ms | 13.614 ms |
| 执行计划＋沙箱执行＋干净重基线 | 1.190 ms | 2.202 ms | 7.074 ms |

这些数字只衡量本地确定性参考模型，不包含外部RSR、云服务、真实Agent、数据库或硬件执行延迟。

## 七、真实边界

1. 内置情景模型是可重复的参考影响模型，不是真实行业预测器。
2. 外部Provider只有实现`rollback`时，外部副作用才能被证明撤销。
3. 当前AAF与RFE是协议对象接入，不等于正式联网运行时已经联调完成。
4. 当前没有分布式隔离容器、多人协商、长期分支存储和生产数据库。
5. RBF无权自行批准，也不能自行创造权威Generation。
