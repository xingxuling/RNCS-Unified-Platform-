# 游戏逻辑的命名边界反演：从脚本到现实行为织构

## 异常

传统游戏逻辑被拆成脚本、事件、状态机、行为树、任务、权限、存档和调试器。它们分别维护状态和生命周期，最后由开发者手工保证一致。

## 旧名称隐含的边界

“脚本系统”默认：

- 逻辑属于某段代码；
- 代码可以直接改变世界；
- 调试、存档和网络是外围问题；
- NPC、玩家、任务和 Agent 使用不同逻辑框架。

## 反演

游戏逻辑的本质不是代码，而是：

```text
谁在什么状态下
因为什么事件
依据什么条件与权限
可以令世界发生什么变化
以及如何证明、恢复和重放这次变化
```

因此新对象不是 Script，而是 **Behavior Transition**：

```text
主体 + 输入/事件 + 条件 + 状态 + 行为计划
+ 能力 + 权威 + 状态变化 + Trace + Evidence
```

## 新定义

**Reality Behavior Fabric 是把主体行为、规则、状态机、行为树、能力调用和可验证状态迁移统一起来的确定性行为运行层。**

## 生活例子

传统自动门常被理解为“传感器触发开门脚本”。现实行为织构会表达：

```text
主体靠近
→ 传感器产生事件
→ 门处于可开启状态
→ 主体满足通行权限
→ 电机能力可用
→ 门从关闭迁移到开启
→ 记录时间、原因和结果
```

同一结构也可用于敌人攻击、审批流程、机器人抓取或 Agent 修改文件。

## 与传统引擎的区别

Godot 的节点、信号、脚本、AnimationTree 与行为插件足够成熟；RBF v0.1 的差异不是功能数量，而是把权威、证据、重放和跨运行时能力作为行为的原生组成部分。
