# RFE Core SDK v0.1.0 开发验收报告

**验收日期：2026-06-30**  
**目标：把 RFE 的本地现实语义与连续性能力提炼为普通项目可以直接调用的稳定 SDK。**

## 1. 验收结论

RFE Core SDK v0.1.0 已完成最小生产前闭环：

```text
Identity / Fact / Relation
→ 候选事务
→ 完整性与引用验证
→ Authority Event
→ 原子 Generation 提交
→ Evidence Root / Commit Receipt
→ RNCS Generation Reference
```

本版本适合协议验证、桌面或服务端原型、小型本地应用和后续 RNCS 模块接入。它不是分布式数据库，也没有把本地文件锁冒充为联盟共识。

## 3. 上游 RFE 兼容性

### C1 Canonical

原 RFE v1.0.0 的 `c1-canonical.json` 全部向量通过：

- null / boolean / integer / negative zero；
- 普通浮点；
- 转义字符串；
- 中文与扩展 Unicode；
- 数组；
- UTF-16 键排序对象。

### C4 Proof Persistence Generation

原 RFE v1.0.0 的 C4 门状态持久化 fixture 已验证：

- Generation 完整性根正确；
- 引用内容对象存在；
- 内容地址与对象完整性根一致。

本验收没有重新编译 Rust；当前环境不存在 Cargo / Rust 工具链。

## 5. RNCS 原生提交

已验证：

```text
RNCS Proposed Envelope
→ Authority Approved
→ RFE Core 原子提交
→ Generation 1
→ Commit Receipt
→ 同一 Envelope 进入 committed
```

测试生成的项目事实可被 RFE 查询，Envelope 重新验证通过。该链路不是旧格式导入，而是 RNCS Contract 直接调用 RFE 提交端。

## 6. 分支与合并

已验证：

- 从指定 Generation 创建分支；
- 比较两代现实的 Identity / Fact / Relation 差异；
- 非冲突事实可合并；
- 同一事实被两个分支修改为不同值时，返回显式 Conflict；
- 冲突时不交换目标分支指针。

Merge 采用保守策略，不会在无法证明安全时自动猜测。

## 7. 篡改与失败原子性

已验证：

- 修改内容对象后，深度验证失败；
- Generation 标记与根不一致时拒绝读取；
- 悬空 Relation 端点导致事务失败；
- 事务失败后当前分支 Generation 不变；
- 旧 base Generation 提交被乐观并发控制拒绝。

## 8. 性能基线

文件后端、单进程、50 次连续事实更新与 500 次查询：

| 操作 | 中位数 | P95 | 最大值 |
|---|---:|---:|---:|
| 原子提交 | 12.985 ms | 26.625 ms | 35.811 ms |
| 当前事实查询 | 4.630 ms | 9.494 ms | 12.128 ms |

最终 Revision：51。

该基线只说明当前小型文件后端的行为，不代表大型数据库或多节点吞吐。当前事件账本和同谓词历史仍会随 Generation 增长，后续需要分页段与数据库后端。

## 9. 项目边界

### 已完成

- Local Core；
- Python 完整参考实现；
- Node 核心读写实现；
- RNCS 提交端；
- Generation Reference；
- Federation Candidate；
- 上游 C1 / C4 兼容验证。

### 未完成

- C7–C12 Federation Bridge 网络连接；
- 生产签名与密钥基础设施；
- 大对象与增量同步；
- 长期百万级 Fact / Relation 压力测试；
- 多进程及多主机并发；
- Rust 原生编译与跨运行时性能对照。

## 10. 最终判断

RFE 的核心能力现在第一次可以由普通项目用简单 API 调用，而无需直接理解 C7–C12 联盟拓扑。Local Core 与 Federation 的边界已冻结：

```text
本地提交成功
≠
联盟共识成功
```

本地 Generation 只能生成 `candidate-not-federated` 候选；必须经过后续 RFE 联盟层证书，才能成为共享现实。
