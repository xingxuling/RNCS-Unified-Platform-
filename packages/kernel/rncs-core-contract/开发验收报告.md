# RNCS Core Contract v0.1.0 开发验收报告

## 结论

RNCS 第一份跨项目共同契约已形成可执行闭环，解决了当前 RFE、HNAC、Living Artifact、ICAR、RSR、VSR 与 Reality Studio 之间“连续性同名但不等价”的核心问题。

## 已冻结的上位规则

- 只有 **RFE Generation** 可以声明权威现实改变。
- HNAC 本地 `generation` 通过适配器降级为 `snapshot_sequence`。
- Living Artifact Revision 仅为语义对象修订。
- ICAR Session 仅为意图执行记录。
- RSR Snapshot 仅为候选模拟状态。
- VSR/AER State 仅为观察者投影。

- 浮点数禁止进入跨运行时核心哈希，避免 Python/JavaScript 数值序列化漂移。

## 已验证的现实意义

在旧结构中，同一次操作会产生 HNAC Generation、LAF Revision、ICAR Session、RFE Receipt、VSR Sequence 等多个近似“版本”。

在新结构中：

```text
局部修订 / 快照 / 会话 / 投影
            ↓ 作为引用进入
Reality Transition Envelope
            ↓ 权威裁决
唯一 RFE Generation
```

所有模块终于可以回答：这些局部记录是否属于同一次现实变化。

## 当前边界

- v0.1 是合同与参考运行时，不替代 RFE 的共识与权威提交。
- 现有项目仍需逐个升级为原生输出/消费 Envelope；当前适配器用于迁移过渡。
- Gateway v0.3 应基于本合同做模块发现与路由，不再复制运行时源码。
