| 目标 | 当前能否开始 | 当前可达到 | 尚缺关键能力 |
|---|---|---|---|
| RCL 少数据智能体 | 是 | 参考运行时中的规则/知识/理解/创造/执行闭环；可按模块组织 | C VM 原生知识与认知域、持久记忆、事件循环、Provider ABI |

## 1. “RCL 原生”的两个口径

- **语言原生**：智能逻辑以 RCL 的知识、内在、理解、创造、权界与执行语义表达。当前已经具备最小闭环。
- **VM 原生**：上述域全部由 C `rclvm` 直接执行，不依赖 Node 参考运行时。当前尚未达到；native VM 仍明确拒绝知识/认知等 Provider 域。

因此当前可以制造 RCL 主导、模型可选的少数据智能体，但不能称为完全脱离宿主的原生通用智能。

## 2. 地球沙盒

合理第一版不是逐原子地球，而是层级网格：

```text
地球 → 区域瓦片 → 气候单元 → 生态单元 → 城市/组织 → 主体
```

RCL 负责规则、事实、权限、知识和因果；RSR/数值计算负责流体、气候与物理；VSR负责投影；真实数据源作为 Provider。少数据路线可以降低训练需求，但不能替代地形、气候和人口基础数据。

## 3. RCL 源百科

RCLpedia 的基本单元应是可执行知识声明，而不是纯文本页面：

```text
实体 + 声明 + 时间/空间范围 + 来源 + 证据 + 置信度 + 冲突 + 修订
```

它既能服务智能体，也能成为地球沙盒的知识层。该项目在四者中最适合立即进入正式原型。

## 4. 第三手机操作系统

应分三级：

1. **OS Shell**：运行在 Android/Linux 上，RCL 管理应用、权限、Agent、世界和工作流；当前可做。
2. **独立 Linux Userspace**：选定设备可启动，拥有自己的桌面、包格式、应用模型和更新系统；需要原生 UI、Provider ABI、文件/网络/设备服务。
3. **完整消费级移动 OS**：兼容多设备并与 Android/iOS 竞争；当前不可宣称，需要驱动、基带、认证、应用生态和长期硬件合作。

## 5. 推荐顺序

```text
Stage-4 模块系统
→ Stage-5 自托管 RBC/包构建
→ Provider ABI + 异步/持久化
→ RCLpedia
→ RCL 原生少数据 Agent
→ Earth Sandbox 多尺度原型
→ Mobile OS Shell
→ 选定硬件上的独立 Linux Userspace
```
