# DML Remote Link v0.2 架构与边界

## 目标

让 Lovable 中的数字蓝天机工作台在不开放用户电脑入站端口的情况下，安全连接本机 DML Core Runtime。

```text
Lovable Workbench
→ 浏览器低权限会话凭证
→ HTTPS Secure Relay
← 本机 DML Host 主动轮询
→ DML Core / CNP / AAF / Gateway / HNAC Provider
→ 本机项目、软件与设备
```

## 为什么不是传统业务 API

浏览器发送的是 `dml.semantic-action.v0.1`，本机返回的是 `dml.workbench-projection.v0.1`。HTTP、SSE 与长轮询只承担传输，不定义任务、文件、审批或能力边界。

## 核心不变量

1. 本机不开放公网入站端口。
2. Relay 不读取项目文件，不执行本机命令。
3. 浏览器不持有主机私钥。
4. Host 只执行本地策略允许的 DML Action。
5. 任意远程身份字段在主机边界被剥离，主体与所有者由本机 DML Runtime 决定。
6. Relay 发往 Host 的动作使用 Ed25519 签名。
7. Host 返回的执行回执与投影使用 Ed25519 签名。
8. Host 请求使用时间戳、随机数和签名，防止伪造与重放。
9. 同一 `action_id` 通过本机执行账本保证幂等。
10. 高风险现实提交仍由 AAF 与 DML Authority 决定。

## v0.2 的真实性边界

- Relay 的状态后端是本地 JSON 参考实现，不是多节点数据库。
- HTTPS 由 Caddy、Nginx、Cloudflare Tunnel 或部署平台提供；内置服务器只提供 HTTP。
- 浏览器会话令牌属于低层远程控制凭证，生产版本仍应升级为账号登录、WebAuthn 与短期授权。
- 本机进程和设备执行依赖 HNAC/HNAF v0.8 Provider；本包本身不绕开其沙盒和授权。
- 当前没有互联网规模的 Provider 市场、计费、组织治理或硬件功能安全认证。
