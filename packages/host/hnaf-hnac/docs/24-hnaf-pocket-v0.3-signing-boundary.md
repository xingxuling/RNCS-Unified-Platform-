# HNAF Pocket v0.3 接入与签名边界

## 已完成

`android-pocket-v0.3-source/assets/pocket.html` 已接入：

- HNAC Format 0.6；
- 手机、平板、无障碍三类本地投影；
- 语义快照；
- 应用操作按钮与意图证据；
- `interface.projected` 运行证据；
- 原有内置签名策略文件。

## 为什么没有直接交付 APK

Android 判断“是否为同一应用升级”时，不只看包名，也要求新 APK 使用同一签名私钥。现有 APK 只能提供证书和公钥，不能提供私钥。另行生成 keystore 会造成签名不一致，通常只能卸载旧版后重新安装，并破坏应用数据和升级连续性。

因此安全路线是：

```text
获得原 keystore
→ 合入 v0.3 源码
→ 使用原 alias / 密码签名
→ apksigner verify
→ 真机覆盖安装验证
```

## 验收要求

正式 APK 发布前至少验证：

1. 包名与旧版一致；
2. 签名证书 SHA-256 与旧版一致；
3. 可直接覆盖安装；
4. 旧版本地状态仍可读取；
5. 手机和平板投影可切换；
6. 无障碍模式可线性读取；
7. 胶囊完整性失败时拒绝运行。

## 禁止的伪升级

- 使用新密钥重签后仍称“可覆盖升级”；
- 修改包名绕过签名冲突却称为同一应用；
- 只改 WebView 页面版本号而不验证 APK 签名；
- 在没有真机安装证据时宣称 Android 发布完成。
