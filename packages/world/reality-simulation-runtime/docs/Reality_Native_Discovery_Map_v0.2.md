# 0. 执行摘要

上一版发现的核心是：

> 文件、数据库、应用、操作系统、游戏引擎、工作流、Agent、网络与安全，可能不是完全不同的东西，而是同一套现实结构在不同历史阶段形成的不同产品。

这一版继续向外扫描后，得到一个更通俗也更大的结论：

> **软件负责让规则行动起来，硬件负责让现实被感知和改变，现实应用负责把两者围绕人的目标接成闭环。**

今天的软件和硬件之所以复杂，常常不是因为事情本身必须这么复杂，而是因为历史上每解决一个问题，就单独做了一类产品：

- 想保存内容，于是有了文件；
- 想查询内容，于是有了数据库；
- 想使用功能，于是有了App；
- 想让两个App合作，于是有了API；
- 想自动完成工作，于是有了工作流和Agent；
- 想把结果放到真实世界，于是有了机器人、物联网和各种设备。

结果是，用户要在很多软件之间搬运信息，开发者要反复实现身份、权限、状态、历史、同步和界面。

现实原生计算试图把这些重复问题重新压缩成一条共同闭环：

```text
谁正在行动
→ 他想做什么
→ 当前有哪些能力
→ 是否有权这样做
→ 世界会发生什么变化
→ 变化是否真的成立
→ 如何留下证据和历史
→ 应该通过什么设备让人感知结果
```

这条闭环既可以生成普通软件，也可以控制机器人、XR设备，最终还可以成为神经接口虚拟世界的底层骨架。

但本文件不会宣称已经完成这些目标。目前真正完成的是：

- 现实连续性和权威的参考内核；
- 意图、能力协商与授权链；
- 持续数字对象格式；
- 二维世界的资产、行为、模拟、渲染、编辑与构建原型；
- 跨宿主运行和Android宿主的早期验证。

仍未完成的是：

- 成熟3D世界；
- 大规模共享现实；
- 生产级硬件控制；
- 医疗级神经信号读取与写入；
- 大量真实用户和长期运行验证。

# 2. 一个统一的现实闭环

无论是发送邮件、审批报销、控制机械臂、玩游戏，还是未来用神经信号移动虚拟身体，背后都可以拆成八步：

```text
1. 观察：现在发生了什么？
2. 意图：主体想要什么结果？
3. 能力：哪些人、软件或设备能完成？
4. 权威：谁有权让它发生？
5. 执行：现实或虚拟世界发生变化。
6. 证据：如何证明变化真的发生了？
7. 连续性：变化怎样进入历史并继续存在？
8. 投影：主体通过屏幕、声音、触觉或神经信号感知结果。
```

## 一个生活例子：开智能门锁

传统结构可能是：

```text
手机App
→ 云端服务器
→ 门锁API
→ 蓝牙或Wi-Fi
→ 门锁控制器
```

现实原生结构关心的是：

```text
谁要开门？
→ 为什么要开？
→ 他现在是否有权限？
→ 哪个设备能执行？
→ 门是否真的打开？
→ 谁在什么时候开过门？
→ 如果网络断开，怎样安全恢复？
```

门锁App只是其中一种界面，不是事情的本质。

## 现有项目映射

| 闭环部分 | 现有项目 |
|---|---|
| 现实事实与历史 | RFE、Living Artifact |
| 主体与跨项目语义 | RNCS Core Contract |
| 意图与预览 | ICAR |
| 能力发现与组合 | CNP |
| 授权与撤销 | AAF |
| 动态运行时入口 | Reality One Gateway |
| 候选分支与比较 | Reality Branch |
| 世界行为与规则 | Reality Behavior |
| 物理、时间和体验演化 | RSR |
| 视觉投影 | VSR |
| 制造环境 | Reality Studio |
| 构建与发布 | Reality Build |
| 跨宿主执行 | HNAC/HNAF |

# 3. 软件领域重点发现

# 3.1 文件不是“盒子”，而是持续存在的对象

## 传统理解

文件是装文字、图片或数据的盒子。

## 名称造成的限制

文件通常只知道自己的字节，不知道：

- 它是谁；
- 为什么存在；
- 谁可以修改；
- 它从哪个版本变来；
- 它和其他对象有什么关系；
- 它能执行什么行为；
- 它应该以网页、表格、App还是XR物体呈现。

## 反演后的结构

> 数字内容应该像现实物品一样，有身份、历史、关系、权限和不同使用方式。

## 生活例子

一份“项目计划”不应该分别存在Word版、Excel版、网页看板版和App任务版。它们可以是同一个对象的不同观看方式。

## 现有项目

Living Artifact Format、RFE、Reality Studio资产连续性。

## 尚未解决

超大文件、实时多人编辑、复杂媒体格式、行业专用语义合并。

---

# 3.2 App不是功能盒子，而是临时组合出来的能力

## 传统理解

用户先找到一个App，再打开它，学习它的按钮，最后完成任务。

## 真正需求

用户通常不关心App叫什么，只关心：

- 帮我订票；
- 把这份资料整理好；
- 把门打开；
- 把游戏发布到手机；
- 找出最安全的执行方案。

## 反演后的结构

> 用户先说目标，系统再寻找有权限、有能力、当前可用的软件或设备来完成。

## 生活例子

不是先决定用哪把螺丝刀，而是先说“把桌子装好”，工具由系统选择。

## 现有项目

CNP负责找能力，ICAR负责形成方案，AAF负责判断能不能做，HNAC/HNAF负责跨设备执行。

## 尚未解决

自然语言意图编译、庞大的能力注册市场、远程Provider、商业计费和服务质量。

---

# 3.3 API不是固定插口，而是能力协商

## 传统理解

一个软件想调用另一个软件，必须提前知道网址、参数和返回格式。

## 问题

只要版本、供应商或设备变化，集成就可能坏掉。

## 反演后的结构

> 系统描述“我需要什么结果、允许多大风险、预算多少、要留下什么证据”，再让多个能力提供者竞争或组合。

## 生活例子

像打车：乘客说目的地，不需要知道司机发动机的API参数。

## 现有项目

Capability Negotiation Protocol与Reality One Gateway已经形成确定性发现和路由原型。

## 尚未解决

互联网规模注册、动态价格、服务信用、网络攻击与跨组织协议治理。

---

# 3.4 数据库不是“存数据”，而是维护什么事实成立

## 传统理解

数据库保存表格、记录或文档。

## 问题

很多系统只保存最后结果，却难以回答：

- 谁改的；
- 为什么改；
- 当时是否有权；
- 哪条历史才是真实历史；
- 断电后如何恢复同一现实。

## 反演后的结构

> 数据库应维护“什么成立、为什么成立、谁允许它成立、它从哪里演化而来”。

## 生活例子

银行余额不只是一个数字，还必须知道每一笔变化的来源、授权和证据。

## 现有项目

RFE Constitutional Reality、RFE Core SDK。

## 尚未解决

生产密码学、大规模数据库后端、全球网络部署和长期运维。

---

# 3.5 工作流不是固定步骤，而是合法的现实变化路线

## 传统理解

工作流是“先做A，再做B，然后审批C”。

## 问题

现实经常出现例外、权限变化、风险升级和中途恢复，固定流程很容易僵硬。

## 反演后的结构

> 系统不只记步骤，而是持续判断“从当前状态到目标状态，哪些变化合法、安全、可逆”。

## 生活例子

报销不是点击五个页面，而是确认费用真实、责任人有权、预算足够、证据完整，最后改变公司账务现实。

## 现有项目

Reality Behavior、CNP、AAF、RFE、Reality Branch。

## 尚未解决

复杂企业制度、法律规则解释、多组织协作和大量真实案例。

---

# 3.6 安全不是“挡住坏人”，而是控制谁能改变现实

## 传统理解

安全主要是账号密码、访问控制、防火墙。

## 更本质的问题

即使一个人成功登录，也不代表他有权：

- 转走全部资金；
- 修改重要历史；
- 控制机器人撞向人；
- 让Agent替自己签合同；
- 在神经接口中提高刺激强度。

## 反演后的结构

> 安全的核心是：谁在什么条件下，可以把现实从A改成B，并且能否撤销、追责和恢复。

## 生活例子

拿到办公室钥匙，不等于有权卖掉办公室。

## 现有项目

AAF、RFE、RNCS Core Contract、Reality Branch预览。

## 尚未解决

生产级身份、硬件可信根、企业IAM、法律责任和神经安全认证。

---

# 3.7 Agent不是聊天机器人，而是被委托的行动主体

## 传统理解

Agent是会调用工具的AI。

## 问题

只要Agent可以真正行动，就必须回答：

- 它代表谁；
- 权限从哪里来；
- 能做多久；
- 能不能转授权；
- 怎样撤销；
- 出错由谁负责。

## 反演后的结构

> Agent是一个获得有限委托的行动主体，而不是拥有无限工具权限的聊天窗口。

## 生活例子

请助理订机票，不等于允许助理卖掉房子。

## 现有项目

AAF、CNP、ICAR、Gateway、RFE。

## 尚未解决

长期Agent身份、跨平台责任链、在线审批与现实法律承认。

---

# 3.8 操作系统不是管理进程，而是协调主体、能力与设备

## 传统理解

操作系统管理文件、内存、进程和硬件。

## 历史限制

它通常不知道用户真正的目标，也不知道一个动作在现实中的意义。

## 反演后的结构

> 未来的操作系统可能先理解目标，再协调软件、Agent和设备，并保证所有现实变化有权限、有证据、可恢复。

## 生活例子

用户说“我要开始会议”，系统自动组合日历、摄像头、麦克风、文档、翻译和会议室设备，而不是让用户打开六个App。

## 现有项目

Reality One Gateway、CNP、AAF、HNAC/HNAF、RFE。

## 尚未解决

硬件驱动、进程隔离、资源调度、桌面生态和大规模兼容性。

---

# 3.9 浏览器不是网页查看器，而是通用现实宿主

## 传统理解

浏览器打开网站。

## 反演后的结构

> 浏览器可以成为加载现实对象、能力包、身份权限和不同交互投影的通用宿主。

## 生活例子

同一个项目对象，在电脑上显示完整编辑器，在手机上显示审核界面，在XR中变成可以走进去的空间。

## 现有项目

HNAF、Living Artifact Host、Reality Studio离线工作台、Web构建链。

## 尚未解决

原生设备权限、后台运行、系统级集成和性能上限。

---

# 3.10 IDE不是写代码的地方，而是把目标编译成系统

## 传统理解

开发者在IDE里编辑代码。

## 反演后的结构

> 开发环境应该允许人描述目标、规则、世界、权限和验收条件，再自动生成代码、配置、测试、界面和发布产物。

## 生活例子

制作一扇游戏里的门，用户描述“只有拿到钥匙的人能打开，打开后守卫会听见”，系统自动形成资产、行为、权限、声音和测试。

## 现有项目

Reality Studio、RAGF、Reality Behavior、RSR、VSR、Build Fabric。

## 尚未解决

自然语言制造、成熟Inspector、脚本调试、插件生态、完整3D和大型项目协作。

---

# 3.11 版本控制不是管理代码，而是管理可能的现实

## 传统理解

Git保存文件版本和代码分支。

## 反演后的结构

> 分支可以描述不同的产品路线、组织决策、游戏世界、机器人动作计划或人生方案，然后比较和合并。

## 生活例子

公司不是复制五份Excel讨论方案，而是创建五条候选现实，分别模拟成本、风险和结果，再选择一条提交。

## 现有项目

Reality Branch Fabric、RFE、Living Artifact。

## 尚未解决

复杂语义合并、多人协商、真实预测准确性和大型分支存储。

---

# 3.12 游戏引擎不是画面引擎，而是可控制的人工现实

## 传统理解

游戏引擎负责场景、物理、脚本、渲染和发布。

## 更大的边界

神经接口虚拟世界需要的不只是画面，还需要：

- 主体身份；
- 身体状态；
- 世界事实；
- 物品所有权；
- 因果历史；
- 多主体关系；
- 安全退出；
- 多感官投影。

## 反演后的结构

> 游戏引擎应成为一个能够制造、运行、证明和投影人工现实的系统。

## 生活例子

玩家拿到一把剑，不只是内存里某个变量变成1，而是世界确认“这把剑属于谁、从哪里获得、是否能交易、损坏后如何连续存在”。

## 现有项目

现有RNCS项目已经覆盖现实内核、资产、行为、模拟、渲染、编辑和构建的参考链。

## 尚未解决

成熟3D、多人持续世界、空间音频、具身反馈和神经接口。

# 3.13 搜索不是找文字，而是发现下一步可做什么

## 传统理解

搜索系统返回网页、文件或答案。

## 反演后的结构

> 搜索除了告诉你“有什么”，还应该告诉你“当前能做什么、需要什么权限、结果会怎样”。

## 生活例子

搜索“申请公司牌照”，系统不只给链接，而是根据身份、地区和材料状态生成可执行路线。

## 现有项目

CNP的能力发现、Living Artifact语义对象、ICAR目标计划。

## 尚未解决

大规模知识索引、事实可信度、法律更新和公共能力注册。

# 3.14 云计算不是租服务器，而是按需提供现实能力

## 传统理解

云平台出租计算、存储和数据库。

## 反演后的结构

> 云可以根据任务提供完整能力，包括计算、模型、数据、权限、设备连接和证据，而不只是虚拟机。

## 生活例子

用户请求“生成并发布一个多人虚拟展馆”，云端自动组合生成、渲染、网络、审核和发布能力。

## 现有项目

CNP、Gateway、HNAC/HNAF、Build Fabric提供早期协议基础。

## 尚未解决

真实云调度、成本模型、弹性扩缩、跨区域合规和生产运维。

# 4. 现实应用领域的反演结果

现实应用不是“把某行业做成一个App”，而是维护这个行业中真正重要的状态变化。

| 领域 | 传统产品边界 | 反演后的核心 | 通俗例子 | 当前承接能力 |
|---|---|---|---|---|
| 企业管理 | ERP、CRM、审批系统分开 | 组织里谁拥有何种责任、资产和任务，以及状态怎样合法变化 | 招聘员工不是填五套表，而是让一个人的组织身份、权限、设备和薪酬同时生效 | RFE、AAF、LAF、CNP可承接原型 |
| 教育 | 课程、作业、考试平台 | 学习者的理解和能力怎样真实改变 | 不只记录“看完视频”，而是记录会不会、错在哪里、能否迁移 | 需要学习状态模型 |
| 医疗 | 病历、预约、设备系统分开 | 人的健康状态连续性与干预证据 | 药物、症状、运动和设备数据进入同一健康历史 | 架构可承接，医学验证远未完成 |
| 法律合同 | 静态文本和人工执行 | 条件满足后，权利义务如何生效、变更和补救 | 租约到期后自动提醒并生成合法处理选项 | LAF、AAF、RFE可做低风险原型 |
| 金融 | 账户和交易记录 | 价值、所有权、承诺、风险与证据 | 钱不是数据库数字，而是有来源、有授权的价值状态 | RFE适配度高，监管门槛高 |
| 制造 | CAD、BOM、生产、维护割裂 | 一个产品从想法到报废的完整身份和历史 | 一台机器的设计、零件、质检、维修属于同一对象 | LAF、资产连续性、RFE适配度高 |
| 物流 | 订单、仓库、运输系统割裂 | 物品在哪里、由谁负责、下一步怎样合法移动 | 包裹每次交接都形成有证据的责任变化 | RFE、AAF、硬件桥接可承接 |
| 城市与建筑 | BIM、IoT、工单分开 | 空间、设备、人员和规则组成持续现实 | 电梯故障不只报警，还自动形成影响范围、维修权限和疏散方案 | 需要大规模空间和设备模型 |
| 科研 | 论文、数据、代码分散 | 假设、方法、数据和反证组成可执行证据图 | 别人可以沿着证据链重现实验，而不是只读结论 | LAF、RFE、Branch适配度高 |
| 政务 | 每项服务一个门户 | 公民资格、权利和状态变化 | 用户说“我要开公司”，系统组合所有合法步骤 | 技术可原型，制度集成很难 |
| 娱乐世界 | 游戏、影视、小说分开 | 同一个世界模型投影成不同媒介 | 一个角色可同时出现在小说、动画、游戏和XR中，并保持同一历史 | RAGF、RSR、VSR、Studio直接相关 |
| 个人生活 | 日历、笔记、健康、财务分开 | 个人目标、承诺、资源和记忆的连续性 | 搬家目标自动协调预算、时间、物品和服务 | 适合低成本验证，但隐私要求高 |

## 现实应用领域的共同发现

这些行业表面上差异很大，但都在重复处理：

```text
主体
+ 资产
+ 规则
+ 权限
+ 状态
+ 时间
+ 证据
+ 下一步行动
```

差异主要在规则和专业知识，不在底层闭环。

这意味着RNCS更适合成为行业系统的共同内核，而不是自己一次性做完所有行业产品。

---

# 5. 硬件领域的反演结果

硬件领域最大的发现是：

> **硬件不是孤立设备，而是现实闭环中的感知器官、执行器官、记忆器官和投影器官。**

# 5.1 传感器不是“采集数据”，而是提供现实证据

摄像头、麦克风、温度计和脑电设备都在回答：现实现在是什么状态？

问题在于，传统系统经常只保存数值，不保存：

- 谁采集；
- 何时采集；
- 是否可信；
- 设备是否校准；
- 数据能支持什么结论。

反演后，传感器输出应成为带来源、时间、可信度和权限的证据。

**现有承接：** RFE Evidence、RNCS Core Contract。  
**缺口：** 真实设备驱动、校准标准、时间同步和硬件签名。

---

# 5.2 执行器不是“接收命令”，而是获得授权后改变现实

机械臂、电机、门锁、汽车和医疗刺激器都能改变现实。

传统控制往往关注指令格式；现实原生控制还必须关心：

- 谁要求执行；
- 是否安全；
- 当前环境是否允许；
- 能否撤销；
- 失败后如何恢复；
- 如何证明执行结果。

**生活例子：** 机器人不是收到“向前一米”就盲目执行，而是先确认前方是否有人、操作者是否有权、紧急停止是否有效。

**现有承接：** CNP、AAF、Reality Branch、RFE。  
**缺口：** 实时控制、确定性时延、功能安全认证和硬件急停。

---

# 5.3 手机和电脑不是应用容器，而是能力与感知的本地节点

一台手机同时拥有：

- 摄像头和麦克风；
- 屏幕和扬声器；
- 定位和运动传感器；
- 本地计算；
- 网络连接；
- 用户身份。

它本质上是一个小型“现实交互节点”，不只是装App的盒子。

**现有承接：** HNAC/HNAF、HNAF Pocket、Gateway。  
**缺口：** 更深系统权限、后台服务、跨平台原生运行和完整设备能力协商。

---

# 5.4 屏幕、音响和触觉设备不是输出设备，而是体验投影器

同一个世界事件可以投影成：

- 画面；
- 声音；
- 震动；
- 触觉阻力；
- XR空间感；
- 未来的神经感知。

因此系统应先描述“想让主体感受到什么”，再根据设备决定怎样表现。

**生活例子：** 游戏中的爆炸，在电脑上是画面和声音，在手柄上有震动，在XR里有空间声和触觉，在无障碍模式中可以转成高对比提示。

**现有承接：** VSR、RSR、Observer Projection。  
**缺口：** 标准化触觉、空间音频、感知等价和神经编码。

---

# 5.5 机器人不是工具，而是具身行动主体

机器人拥有身体、传感器、能力和行动后果。

如果它只能接收命令，它只是复杂机器；如果它能理解目标、选择能力、接受授权、留下证据，它就接近具身主体。

但“主体”不等于拥有与人相同的权利，它仍然必须明确责任边界和控制权。

**现有承接：** Subject、CNP、AAF、Behavior、RSR、RFE。  
**缺口：** 实时机器人中间件、运动规划、硬件安全和真实世界数据。

---

# 5.6 汽车不是交通工具，而是移动现实节点

现代车辆同时是：

- 传感器平台；
- 计算平台；
- 具身执行器；
- 人员与货物空间；
- 高风险安全系统。

现实原生结构可以统一驾驶意图、道路环境、车辆能力、法规和执行证据。

但这一领域对安全和法规要求极高，不适合当前直接进入产品开发。

---

# 5.7 智能家居不是很多联网设备，而是一个有规则的生活空间

传统智能家居往往是每个灯、门锁、空调各有一个App。

反演后的目标是：

> 房间知道谁在里面、当前意图是什么、哪些设备可用、什么变化安全，并统一执行。

**生活例子：** “我要睡觉”可以同时降低灯光、调整温度、锁门和关闭通知，而不是操作四个App。

**当前价值：** 非常适合作为现实原生硬件闭环的低成本验证场景。  
**缺口：** 设备协议碎片化、隐私、离线可靠性和安全认证。

---

# 5.8 芯片、存储和网络分别是执行、连续性和共享现实的物理基础

- 芯片负责执行能力；
- 存储负责让状态持续存在；
- 网络负责让多个主体对同一现实协调。

RNCS目前主要在软件语义层工作，不需要马上自造芯片或网络设备。

更合理的路线是先定义稳定的协议和运行时边界，未来再决定哪些能力值得下沉到硬件。

---

# 5.9 神经接口不是新键盘，而是主体与人工现实之间的边界

这是整份文档最重要的硬件反演。

## 传统理解

脑机接口经常被描述为：

- 用脑信号控制鼠标；
- 读取意念；
- 把信息写进大脑。

## 真正问题

神经接口直接接触：

- 意图；
- 注意力；
- 感知；
- 身体感；
- 情绪和疲劳；
- 主体对现实的判断。

因此它不能只是一个输入输出设备。

## 反演后的结构

> 神经接口是主体主权与人工现实之间的安全边界。

它必须保证：

- 不确定意图不能直接执行高风险动作；
- 刺激必须有强度、时间和区域上限；
- 主体可以随时退出；
- Agent不能覆盖人的最终控制权；
- 系统能区分候选感知、实际刺激和权威世界事实；
- 所有关键操作可审计和恢复。

## 现有项目能做什么

- ICAR：把不完整意图变成候选目标；
- CNP：根据设备能力选择输入输出路线；
- AAF：控制高风险神经动作是否允许；
- Branch：执行前模拟结果；
- RFE：记录真正成立的主体和世界变化；
- RSR/VSR：把世界事件转成体验计划；
- HNAC/HNAF：适配不同神经或XR宿主。

## 仍然几乎为空的部分

- 真实神经信号解码；
- 神经刺激编码；
- 生理反馈；
- 医疗安全；
- 长期神经可塑性影响；
- 临床和伦理验证。

因此现阶段正确做法不是假装已经有脑机接口，而是先把接口后面的世界、意图、权威和安全结构做好。

---

# 6. 最有价值的新增发现

## 发现一：软件、Agent和硬件可以共享同一套“能力—权威”协议

一个能力的提供者可以是：

- 一个本地函数；
- 一个云服务；
- 一个Agent；
- 一台机械臂；
- 一套XR设备；
- 一个未来神经接口。

它们的实现完全不同，但上层都可以询问：

```text
你能做什么？
需要什么输入？
风险多大？
谁有权调用？
会产生什么证据？
失败后怎样恢复？
```

这意味着CNP和AAF未来可能不仅是软件协议，也可能成为现实设备和神经设备的共同控制边界。

---

## 发现二：真正统一软件与硬件的不是数据，而是“状态变化”

软件经常强调数据，硬件经常强调信号。

但用户真正关心的是：

- 门从锁定变成打开；
- 钱从账户A转到账户B；
- 角色从健康变成受伤；
- 机器人从静止变成移动；
- 主体从看见黑暗变成感知光亮。

因此共同单位不是数据包，而是：

> 有主体、有原因、有权限、有结果、有证据的状态变化。

RFE和RNCS Transition Envelope正好位于这个共同边界。

---

## 发现三：UI、XR和神经刺激都属于“投影”，只是深度不同

按钮、网页、3D画面、声音、触觉和神经刺激，看起来是不同技术，实际上都在回答：

> 同一个现实状态，应该怎样被当前主体感知和操作？

这让VSR的长期方向不只是渲染器，而是“体验投影计划”的一个实现。

但必须明确：神经刺激比屏幕投影风险高得多，不能因为结构相似就跳过医学验证。

---

## 发现四：神经接口虚拟世界的第一核心不是画质，而是主体连续性

即使未来画面非常真实，如果系统不知道：

- 玩家是谁；
- 身体属于谁；
- 记忆和资产如何连续；
- 哪些感知是模拟；
- 谁可以改变主体状态；
- 怎样退出并恢复现实定向；

它仍然不是可长期生活的虚拟世界。

因此RFE、AAF和主体边界不是附加模块，而是神经接口世界的地基。

---

## 发现五：融资目前不是唯一瓶颈，真实验证资源才是

当前大多数软件协议仍可在低资金条件下继续开发。

真正开始明显需要资金的阶段是：

- 大规模云与多人压力测试；
- 多种GPU、手机和XR设备矩阵；
- 原生构建与签名基础设施；
- 专业美术、音频和游戏内容；
- 机器人与传感器实验；
- 神经接口硬件、实验室、伦理和医学合作；
- 长期用户测试与安全认证。

所以现在“想不到哪里花钱”并不奇怪。当前最大的稀缺资源仍是结构收口、真实样板和可重复验证，而不是盲目扩张团队。

---

# 7. 哪些方向现在不值得直接开发

## 1. 不要立即造通用操作系统

现有能力还没有形成完整硬件驱动、进程隔离和生态。应先通过Gateway、HNAC/HNAF和Studio验证“意图驱动能力组合”。

## 2. 不要立即进入医疗脑机硬件

缺少实验室、医学团队、伦理审批和安全验证。当前应该先定义设备中立协议和安全边界。

## 3. 不要同时做十个行业产品

企业、教育、医疗、金融都可以映射RNCS，但现在同时开发会把统一内核重新撕裂成项目堆。

## 4. 不要继续创造大量独立Fabric名称

新发现应优先进入现有核心层、协议或Studio插件。只有出现真正独立的生命周期、用户和部署边界时，才值得成为新项目。

## 5. 不要把“能生成Demo”当成范式成立

至少需要：

- 一个完整游戏样板；
- 一个非游戏现实应用样板；
- 一个真实硬件闭环样板；

才能证明这套原语确实跨领域。

# 9. 未来三阶段路线

# 第一阶段：统一软件现实闭环

目标：不再让各项目只是能互相导出文件，而是共享同一个主体、世界身份、RFE Generation和证据链。

必须完成：

1. Reality Studio通过Gateway动态调用全部运行时；
2. 一个统一Project/World ID；
3. 资产Revision、模拟Snapshot和视觉Projection全部引用同一RFE Generation；
4. 关键世界事实必须经过AAF和RFE；
5. 完成一个可发布的真实二维游戏；
6. 完成一个非游戏应用样板，例如智能空间或组织审批。

这是目前最高优先级。

---

# 第二阶段：具身虚拟世界与现实硬件桥

目标：让系统不仅处理屏幕中的对象，还能理解身体、空间和真实设备。

必须完成：

- 3D Mesh、PBR、骨骼和物理；
- 空间音频和触觉事件模型；
- 角色身体与姿态；
- 多人持续世界；
- 传感器证据接口；
- 执行器授权接口；
- XR宿主；
- 一个智能家居或小型机器人闭环样板。

---

# 第三阶段：神经接口抽象与安全闭环

目标：在不绑定单一设备的情况下定义神经输入、感知输出和安全边界。

输入结构：

```text
Neural / Physiological Signal
→ Intent Candidate
→ Confidence
→ Subject State
→ Safety Resolver
→ Authorized Action
```

输出结构：

```text
World Event
→ Perceptual Intent
→ Sensory Plan
→ Device Capability Negotiation
→ Safety Limit
→ Physical / Neural Projection
```

第一批验证应从低风险、非侵入式组合开始：

- 眼动；
- 肌电；
- 注意力信号；
- 简单EEG分类；
- XR；
- 触觉设备；
- 生理状态监测。

不要直接从“写入完整感知”开始。

# 11. 反证条件

如果出现以下情况，必须修改甚至否定当前路线：

1. 统一原语使简单应用反而变得明显更复杂；
2. 不同行业的规则无法共享主体、权限、状态和证据模型；
3. 动态能力协商的成本远高于固定API，且没有带来可靠性收益；
4. RFE式连续性无法扩展到真实多人和大型历史；
5. 多种投影无法保持同一对象的语义一致；
6. 硬件实时控制无法容忍权威与证据层的额外时延；
7. 神经安全无法通过软件协议得到有效改善；
8. 用户仍然必须理解所有底层项目才能完成普通任务；
9. 系统只能做演示，无法制造完整产品；
10. 所谓统一最终只是把多个旧系统包在更厚的一层里。

# 12. 最终锚点

## 异常

软件、行业系统和硬件越来越多，却反复处理身份、权限、状态、历史、同步和界面。

## 矛盾

人真正想要的是一个结果，但必须先理解一堆App、设备和接口。

## 本质

所有数字系统与现实设备都可以放进同一个闭环：

```text
观察现实
→ 理解主体意图
→ 发现能力
→ 判断权威与安全
→ 改变现实
→ 留下证据和历史
→ 让主体感知结果
```

## 现实映射

现有RNCS项目已经分别覆盖这条链的大部分软件器官，但尚未完全共享同一现实，也尚未进入成熟硬件和神经验证。

## 方案

先完成统一软件现实闭环，再进入具身3D和硬件桥，最终建立设备中立的神经接口与安全层。

## 最终锚点

> **未来真正重要的软件，可能不再是一个个App；真正重要的硬件，也不再是一台台孤立设备。它们会共同组成一条受主体意图驱动、受权威与安全约束、能够持续改变并反馈现实的能力网络。**

而神经接口虚拟世界，就是这条能力网络最深的一种形态：

```text
世界能够存在
主体能够进入
意图能够改变世界
世界能够反馈主体
整个过程安全、连续、可验证
```
