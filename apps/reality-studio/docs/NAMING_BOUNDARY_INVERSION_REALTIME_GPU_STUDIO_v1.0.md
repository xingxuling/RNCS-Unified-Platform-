# Reality Studio v1.0 实时 GPU 制造：命名边界反演

## 旧名称隐含的边界

传统“编辑器视口”通常被理解为：编辑器内部用于查看场景的一块画布。它与游戏运行、设备画质、发布版本和最终玩家视图经常由不同状态与不同管线维护。

这会产生四类断层：

1. 编辑器里看到的，不一定是运行时真正提交的状态；
2. 高端设备与低端设备的画质切换可能改变重要语义；
3. GPU 命令、资源与权威世界状态之间缺少可验证绑定；
4. 设备不支持 GPU 能力时，系统可能静默伪装或直接失效。

## 反演

```text
编辑器 GPU 视口
→ 观察者相对的实时视觉现实提交界面
```

它不是单纯预览画面，而是：

```text
权威世界状态
+ 当前观察者
+ 设备能力
+ 性能预算
+ 视觉语义
→ 可执行 GPU 帧计划
→ 帧回执与证据
```

## 新边界

Reality Studio v1.0 将视口定义为同一制造会话的实时投影：

- 场景节点仍有稳定身份；
- 行为运行时仍是权威状态来源；
- VSR 负责观察者相对选择、材质、灯光、批处理和后处理；
- WebGPU 只负责执行已编译的视觉现实；
- Canvas Reference 是明确标记的降级投影；
- Frame Root 将来源现实、资源和命令绑定。

## 生活类比

传统流程像建筑师用一套模型、施工队拿另一套图、住户最后看到第三套装修；三者不一致时只能人工核对。

实时 GPU 制造则像同一栋建筑的数字孪生：设计、施工状态、材料清单和住户视角都来自同一对象，只是投影精度不同。
