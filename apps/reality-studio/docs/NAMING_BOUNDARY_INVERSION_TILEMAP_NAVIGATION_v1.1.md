# TileMap 与导航命名边界反演报告 v1.1

## 传统边界

传统 TileMap 通常被理解为“把小图片排成地图”，导航则被理解为“给角色算一条路”。这会让视觉、碰撞、地形代价、行为、运行时和证据分散在不同工具与缓存中。

## 反演后的定义

Reality Studio v1.1 将 TileMap 定义为：

> **具有稳定身份、视觉投影、碰撞约束、移动代价、编辑历史与可验证根的空间现实切片。**

导航被定义为：

> **主体在约束空间中，从当前状态到目标状态的可验证可供性路径。**

因此同一个格子可以同时影响：

- 玩家看见什么；
- 物体能否穿过；
- AI 是否愿意经过；
- 移动成本；
- 运行时热更新；
- 构建与审计证据。

## 生活例子

商场平面图并不只是“地板图片”：墙是碰撞约束，扶梯是特殊通路，施工区是动态阻挡，拥挤区域具有更高通行成本，不同访客还可能拥有不同权限。v1.1 用同一结构表达这些关系，而不是维护四份互相漂移的地图。

## 新闭环

```text
空间意图
→ TileMap身份与层
→ 视觉/碰撞/导航编译
→ 路径查询
→ 主体移动
→ 动态障碍更新
→ 导航收据与投影
```
