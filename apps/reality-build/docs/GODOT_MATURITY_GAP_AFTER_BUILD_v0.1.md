# Reality Build Fabric 后的 Godot 成熟度差距

构建织构解决了此前最明显的一项生产缺口：统一项目可以直接形成可运行发布产物，而不再停在编辑器和 JSON 清单。

## 得到提升的部分

- Web 一键输出；
- 单文件离线分发；
- Windows 免安装便携宿主；
- Android Studio 工程；
- 资产烘焙与内容寻址；
- 构建缓存；
- 完整性校验；
- 发布证据；
- 导出后真实行为一致性。

## 仍落后 Godot 的关键部分

1. Windows、Linux、macOS 原生运行时和可执行文件；
2. Android/iOS 自动工具链、签名和商店发布；
3. GPU 实时渲染后端；
4. 完整输入、窗口、UI、本地化和无障碍；
5. 导航、网络、3D、插件和包管理；
6. Profiler、崩溃报告、增量补丁；
7. 大量设备和驱动兼容验证。

## 工程估算

| 维度 | v0.9之前 | 加入构建织构后 |
|---|---:|---:|
| Godot整体功能广度 | 34%–40% | 38%–44% |
| Godot整体生产成熟度 | 26%–32% | 31%–37% |
| Godot二维运行核心 | 66%–74% | 68%–76% |
| Godot二维完整生产体验 | 50%–58% | 57%–65% |

这些数字是子系统覆盖估算，不是性能跑分。

下一项最值得开发的是 **VSR WebGPU Executor**，因为发布链已能把项目交付出去，但当前视觉执行仍主要依赖 Canvas/CPU参考宿主。
