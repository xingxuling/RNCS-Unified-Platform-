# Changelog

## Unreleased — 2026-09-10

- Reality Build now carries a Studio-owned evaluated Sequence frame through an explicit candidate-only projection. `reality-build.sequence-frame-projection.v0.1` validates canonical roots and explicit animation track/clip/node bindings, lowers the evaluated time through the existing VSR animation-layer seam, and reaches the generated `web-release` payload without adding a second timeline evaluator. A real Chromium/WebGPU run verified `selection=sequence-frame`, `mode=evaluated-frame`, `time=0.25`, `verified=true`, 5 draw calls, 806 triangles and a submitted WebGPU receipt with no device loss. Camera/audio/other Sequence track classes, target-side playback, Android/physical devices, performance and human visual acceptance remain open. Evidence: evidence/BUILD_SEQUENCE_FRAME_PROJECTION_CANDIDATE_v0.1.json.
- The evaluated Sequence projection now also lowers an explicit Studio camera cut: Build validates `camera_binding`, reuses the existing VSR camera list/`activeCameraId` contract, and exposes `cameraId` in the generated browser inspection seam. A real Chromium/WebGPU target with camera+animation frame data retained `camera:alternate`, `selection=sequence-frame`, `time=0.25`, `verified=true`, 4 draw calls, 806 triangles and `submitted=true` with no device loss. Camera transform/lens interpolation, audio/other track classes, target-side playback, Android/physical devices, performance and human visual acceptance remain open. Evidence: evidence/BUILD_SEQUENCE_CAMERA_FRAME_PROJECTION_CANDIDATE_v0.1.json.
- Reality Build now lowers existing VSR animation-layer blending/masks and animation-graph state/transition selections through the same sealed fixed-tick candidate policy used by clip playback. Separate web-release candidates and real Chromium/WebGPU probes advanced layers and graph from Tick 0 → 15 (`0 → 0.25s`) with changing animationRoot, verified frames and 0 application errors; Studio authored Sequence lowering, physical-device/native GPU, performance and human acceptance remain open. Evidence: evidence/BUILD_ANIMATION_GRAPH_LAYER_LOWERING_CANDIDATE_v0.1.json.
- The structured animation graph policy now has a separate Android target receipt: a real Gradle 9.5.1 / Android SDK 35 debug APK was signed, installed and launched on `Rcl_Aether_API35_ATD`; WebView CDP observed `https://rncs.local/`, graph state `run`, the `walk → run` transition and deterministic Tick 0 → 15 (`0 → 0.25s`) frame-root changes with `verified=true`. The emulator reported no usable primary WebGPU adapter and no native GPU submission receipt was claimed. Evidence: evidence/ANDROID_ANIMATION_GRAPH_TARGET_LOWERING_CANDIDATE_v0.1.json.
- Authored Sequence target lowering was audited and kept blocked: Studio `evaluateSequence()` is the existing deterministic owner, while Build has no Sequence consumer, target playback path or explicit 3D VSR clip binding; the raw Build fixture has no persisted `sequencer` field. Evidence: evidence/BUILD_SEQUENCE_TARGET_LOWERING_AUDIT_v0.1.json. The next step requires a canonical choice between Studio-evaluated-frame projection and a shared target-side Sequence runtime.
- Reality Build now lowers a sealed candidate-only fixed-tick VSR animation policy through the existing spatial Tick into initial/per-tick frame compilation and WebGPU rendering. The glTF replace-mesh path preserves imported skin, animation channels and support joint nodes for a single identity render root, and fails closed for ambiguous deformed roots. Build/Web embedded payloads and a real Chromium WebGPU probe verified Tick 0 → 15, animation time 0 → 0.25 seconds, changing animationRoot and 0 application errors; Android remains source-project HTML evidence only. Evidence: evidence/BUILD_ANIMATION_TARGET_LOWERING_CANDIDATE_v0.1.json.
- Audio target lowering archaeology records a real source-derived `sfx-wav` packaged in web-release while proving that the current target only enters the procedural cue oscillator: no explicit cue-to-asset binding, WAV request/decode, or RSR spatial-audio consumer was observed. A legacy Canvas HUD `fillText` coordinate regression discovered during the audit was fixed and covered by a runtime test. This remains `CANDIDATE_NEGATIVE_EVIDENCE_ONLY`; no K400 gate or audio playback claim is promoted. Evidence: `evidence/BUILD_AUDIO_TARGET_LOWERING_AUDIT_v0.1.json`.
- Reality Build now lowers the existing Reality Studio UI tree and input profile into web and embedded Android target hosts. The candidate carries sealed UI/Input roots and manifest data, renders the Studio nodes through a browser DOM/WebView overlay, routes keyboard/touch actions through InputActionRuntime, and drives the existing Behavior tick. Chromium verified node rendering, KeyD movement and KeyP pause; an API 35 ATD emulator verified in-bounds touch controls and a real adb shell input tap reaching ui:right → move_right. This does not establish native GPU UI, physical-device behavior, accessibility/localization acceptance, release signing or human visual acceptance. Evidence: evidence/BUILD_UI_INPUT_TARGET_LOWERING_CANDIDATE_v0.1.json.
- Reality Build spatial payload loading now reuses VSR's `createVSRBrowserAssetCache()` CacheStorage provider in web targets: the candidate host persists SHA-addressed payloads, rehydrates them across Chromium cold reloads, and invalidates the dedicated cache when the rooted scene/payload revision changes. This remains real Chromium candidate evidence; Android, quota/performance, remote coherence and physical-device coverage are tracked separately.
- Android embedded targets now read their packaged `index.html` and load it through `loadDataWithBaseURL("https://rncs.local/", ...)`, giving the existing VSR CacheStorage provider a stable synthetic origin. Source-generated v1/v2 APKs were built with Gradle 9.5.1, run on the API 35 `Rcl_Aether_API35_ATD` emulator, and verified through revision invalidation plus process-restart rehydrate; quota/eviction/performance, physical devices and production release remain open. Evidence: `evidence/ANDROID_ASSET_CACHE_PROVIDER_v0.1.json`.
- Reality Build requests now expose an explicit `asset_cache.enabled/max_bytes` provider policy that enters the build identity; VSR load scheduling can prioritize provider-cached asset ids without changing resolution or authority semantics. A source-generated Android v1/v2 pair ran on the API 35 emulator with a 50,000-byte budget, verified bounded final resident bytes, revision invalidation, and repeatable process-restart hits. Evidence: `evidence/ANDROID_ASSET_CACHE_BUDGET_CANDIDATE_v0.1.json`; WebView quota guarantees, performance curves, physical devices and remote coherence remain open.
- Reality Build requests now also expose `asset_cache.persist_accesses`; the Android/WebView lowering defaults this telemetry to memory-only, while payload writes remain durable through a coalesced manifest flush. VSR cached-id scheduling and provider inspection remain explicit. The optimized source-generated APK pair was re-run on the API 35 ATD profile, with direct/provider controls and 8/32/128 KB bounded-cache probes recorded as candidate evidence; this does not establish a physical-device curve, quota guarantee or remote coherence. Evidence: `evidence/ANDROID_ASSET_CACHE_PERFORMANCE_CANDIDATE_v0.1.json`.
- Large World GLB candidate bundles can now cross the generic presentation seam into content-addressed web-release/embedded target payloads; the browser host reuses `VSRSpatialAssetStreamer` for active-cell byte loading/SHA verification, the existing VSR glTF importer for explicit mesh replacement bindings, and the WebGPU executor for local Chromium draw receipts. This remains candidate-only and does not establish Android/device/production delivery.
- Android target generation now emits parseable independent `debug`/`release` Gradle closures, Windows `.bat`/`.cmd` toolchains are invoked through the shared command adapter with space-safe `cmd.exe` argument handling, and the local `android-apk` path records automatic `apksigner` verification; this closes host APK build evidence, not WebView/device or release-signing evidence.
- The Large World candidate APK now has an Emulator WebView cold-start candidate: the embedded HTML re-establishes RSR/3D roots, payload readiness and 11 explicit bindings through Canvas2D fallback; the emulator has no WebGPU adapter, so physical-device GPU evidence remains open.
- VSR asset residency now exposes a rooted `vsr.spatial-asset-transition.v0.1` receipt; Aether Reality Cell transitions and the Reality Build browser host reuse the same lease-release/over-budget-eviction seam. The fixed Build smoke proves receipt generation, while dynamic cell/camera eviction and performance remain open.
- 构建请求新增 `spatial_trace`，纳入语义构建键并执行两次独立 RSR 空间回放。
- 构建收据新增空间状态根、因果 delta 根、空间 runtime manifest 根和导航 manifest 根。
- VSR WebGPU frame plans now expose dynamic entity vertex ranges and light bindings; browser targets update those buffers from the authoritative behavior Tick and re-verify the resulting resource/frame roots.

## v0.2.0-alpha.1 — 2026-07-02

- 新增 `windows-native`：通过 Go 交叉编译生成 PE32+ Windows GUI EXE。
- 应用 HTML、行为运行时和资产直接嵌入 EXE，不再依赖 BAT、Node.js或外部 HTML。
- 新增 `android-apk`：自动调用 Gradle `assembleDebug`，检查 APK、记录调试签名状态，并在可用时调用 `apksigner` 验证。
- Android 工程新增中文 BAT 与 Shell 一键构建脚本。
- 新增构建工具链与项目能力预检，阻止“没有工具链却伪装构建成功”。
- 构建图新增 `preflight` 节点，收据新增 `preflight_root`。
- CLI 新增 `doctor` 与 `targets`。
- 测试由 91 项增加至 113 项。
