# DML v0.4.2 测试推进与任务看门狗

## 问题

候选代码已经产生，但测试 Provider 的异常结果没有完成状态回写；Windows 子进程还可能在超时后残留，导致任务长期停留在 `running`。

## 修复

1. 活跃任务状态优先于旧事件投影；
2. 错误统一规范为 `{ code, message, evidence }`；
3. Windows npm 优先通过 Node 直接运行 `npm-cli.js`；
4. 超时时使用 `taskkill /T /F` 终止进程树；
5. 候选测试最多执行两次，并记录每次收据；
6. 启动时自动恢复被中断操作；
7. 已持久化为失败的旧版候选测试自动重试一次，记录次数防止循环；
8. 测试通过后继续展示候选结果并等待采用。
