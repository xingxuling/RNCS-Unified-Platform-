# DML 认知运行时 v0.5

## 设计原则

认知模型是可替换的理解与规划 Provider，不是 DML 主体本身。主体状态、权限、工具、任务、证据、记忆和采用权继续由 DML Runtime 管理。

## 输入决策

- `answer`：直接回答；
- `tool`：调用只读本机工具后继续思考；
- `task`：创建可执行、可验收任务；
- `control`：恢复现有任务；
- `clarify`：只询问一个关键缺口。

## 安全边界

- 认知工具只能读取；
- 路径限制在项目根目录内；
- `.env`、`.git`、`node_modules` 等敏感目录不可读取；
- 工具循环最多六步；
- 写入、命令和候选采用仍进入原任务权限与审批系统；
- API 密钥仅保存在本机状态目录。
