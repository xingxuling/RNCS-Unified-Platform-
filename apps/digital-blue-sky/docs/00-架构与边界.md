# 00｜架构与边界

## 本版解决的问题

上一阶段的 Workbench 有正确的工作逻辑，但数据仍是模拟状态。传统做法会为每项功能建立固定接口，例如创建任务、暂停任务、查询产物。DML 原生做法则让界面表达语义动作，由能力网络决定谁来完成。

## 核心链

```text
AIP Node
→ Intent Goal
→ DML Semantic Action
→ CNP Negotiation
→ AAF Authority
→ Provider Execution
→ Work Event
→ Projection
```

## 不变量

1. UI 不能绕过 CNP 直接绑定 Provider；
2. 高风险结果采用不能绕过 AAF；
3. Provider 可替换，事件语义不能被替换；
4. 投影可变化，权威事件和证据根不能伪造；
5. 浏览器传输不是领域边界。
